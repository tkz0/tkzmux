# tkzmux — design

> Living document. Started as the approved planning document (2026-09-07); the design sections were moved here in M0.1 (TKZ-5). Spike results from M1.1–M1.3 are written back into the relevant sections. Tickets live in Linear (see *Roadmap*) and point at sections of this file.

## Executive summary

- **What**: a personal cmux replacement. Sidebar of Claude Code sessions grouped by repo, one terminal per session, app-level git/Claude status bar, Thomas' own design (Claude Design project `452d6955…`, theme *2c Midnight indigo*).
- **Stack**: Swift 6.2, AppKit-first, own Metal renderer, **libghostty-vt** (Ghostty's headless VT core, MIT) as the *only* third-party dependency, vendored as a prebuilt xcframework so daily builds are plain `swift build`. No SwiftUI on hot paths, no Sparkle/Sentry/telemetry.
- **Why this split**: the VT state machine is where decades of correctness live (Claude Code alone needs DEC 2026, kitty keyboard, SGR mouse, OSC 8/52, alt screen). The renderer and surface lifecycle are where cmux's cost lives (2.47 GB, 167 threads, 7–9 % idle CPU for 31 panels). Reuse the former, own the latter.
- **Target**: macOS 26+, arm64 only. Replace cmux as daily driver within weeks; sharing with friends later needs no structural change (see *Sharing readiness*).
- **v1 scope**: one surface per session (no splits), two Claude accounts, session restore, plain groups, cmux keybindings.

## Context

Thomas runs 20 cmux workspaces / 31 panels with ~7 live Claude Code sessions across two subscriptions (`~/.claude` "Private", `~/.claude-alt` "Almi"). cmux (Swift + a 30-patch libghostty fork, GPL-3) is noisy, UX-opaque and heavy. He has a finished design: grouped session sidebar with colour-edged groups, "N working · N need you" strip, one Claude Code terminal per session, status bar (branch, WT badge, model badge, diff stats, ahead/behind, ports, context %, usage %). Motivation for owning the renderer: performance on an M4 Max (36 GB, 7680×2160, macOS 26.6, Xcode 26.1, Swift 6.2). Goal: daily driver within weeks; not (yet) public.

## Evidence (why the plan is not guesswork)

- **What runs in Thomas' terminals** (last 5000 zsh commands): git 762, claude 452, pnpm 155, dotnet 34, pico 38, more 32; no vim/htop/tmux. Terminal must be perfect for zsh + Claude Code.
- **Claude Code 2.1.263 emits** (binary strings): DEC 2026, alt screen 1049 (fullscreen mode), kitty keyboard **`CSI > 5 u`** = `DISAMBIGUATE | REPORT_ALTERNATES` (bits `1<<0` and `1<<2`; **not** REPORT_ALL, which is `1<<3` = 8) on push and `CSI < u` on pop — *measured from `Tests/TkzTerminalCoreTests/Fixtures/claude-boot.tkzrec`: `CSI > 5 u` ×4, `CSI > 1 u` ×0, so the original planning note was wrong. The practical difference from flags 1 is narrow and worth stating precisely: printable keys still send their text, Enter/Tab/Backspace keep `\r`/`\t`/`\x7f`, key releases stay silent, and Shift+Enter is still `CSI 13;2u`. The only observable change is the `:<shifted>` alternate inside CSI u sequences (`Ctrl+Shift+A` → `ESC[97:65;6u` rather than `ESC[97;6u]`). Escape-coding every printable key would need REPORT_ALL, and reporting releases needs REPORT_EVENTS (`1<<1`) — Claude Code requests neither, so `keyUp` and modifier releases legitimately produce zero bytes in our main use case* — plus **DEC 1004** (focus events, so `ghostty_focus_encode` really is needed in v1) and **DEC 2031** (colour-scheme change notification), neither of which was in the original list; SGR mouse 1000/1006, OSC 8, OSC 52, OSC 0 title (which **tracks the running tool**: `✳ Claude Code` idle → `✳ Echo hi` while working — a free "what is this session doing" signal for the sidebar, no hooks needed), OSC 9 notifications, 24-bit + 256 colour, DECRQM, modifyOtherKeys, bracketed paste. **No OSC 7**, so `pwd` stays unset and the cwd must come from `Pty.foregroundProcess()`.

## Terminal engine (TkzTerminalCore / TkzTerminalRender / TkzTerminalView)

### Packaging (chosen: xcframework → `.binaryTarget`; done in M1.1 / TKZ-7)
- **Pinned commit**: `vendor/ghostty-vt/COMMIT` (first pin `82232ec`, Ghostty main 2026-09-07, app 1.3.2-dev, lib version string `0.1.0-dev`). Upgrading = `GHOSTTY_COMMIT=<sha> make vendor`, then diff `vendor/ghostty-vt/abi-types.json` (sorted, pretty `ghostty_type_json()` via `tkzmux-vtdump abi`) and `ghostty.terminfo`; the test `abiManifestMatchesVendoredFile` fails if the binary and the manifest drift. Network only at vendoring time.
- `scripts/build-ghostty-vt.sh` (zig 0.16.x, xcodebuild, tic; ~1 min): shallow-fetches the commit into `$TMPDIR/ghostty-vt-src`, then `zig build -Demit-lib-vt -Demit-xcframework=false -Dtarget=aarch64-macos -Doptimize=ReleaseFast` → `zig-out/lib/libghostty-vt.a` (the SIMD-combined, libSystem-overridden archive) → our own `xcodebuild -create-xcframework -library … -headers <ghostty/**.h + module.modulemap "GhosttyVt", umbrella ghostty/vt.h>` → `vendor/ghostty-vt/ghostty-vt.xcframework` (**arm64-only**, committed). Two ticket assumptions were wrong at this commit and are worked around: (1) Ghostty's own lib-vt xcframework step always lipo's arm64+x86_64 (`-Dxcframework-target` only affects GhosttyKit), which would double the archive; (2) `-Demit-terminfo` installs nothing in lib-vt mode (resources only ship with the app executable), so the script runs an 8-line `zig run` wrapper over `src/terminfo/*.zig` (std-only) to print the terminfo source (`vendor/ghostty-vt/ghostty.terminfo`) and compiles it with `tic -x -o Resources/terminfo` → `78/xterm-ghostty`, `67/ghostty`.
- **Spike results (M1.1)**: zig build 55 s on the M4 Max (first run, includes dependency fetch; a re-run is fully cached and reproduces a byte-identical archive); `libghostty-vt.a` 10.5 MiB arm64, xcframework 11 MB (< 30 MB → committed to git; `.gitattributes` marks only the `.a` `-diff`, so header changes show up in upgrade diffs); **no `-lc++` needed** (0 `std::__1` undefined symbols: vendored simdutf/highway are built no-libcxx); build info: simd=true, kitty-graphics=true, tmux-control-mode=false, ReleaseFast; lib deployment target macOS 13 (we require 26). `swift build` links the static archive with no extra linker settings.
- **Resource layout**: SwiftPM requires resources under the target's `path`, but the repo keeps them at the root. The real directory must live at **`Sources/<Target>/Resources/<X>`** and the repo-root `Resources/<X>` is the **symlink** — *not* the other way round. Verified the hard way (M1.4/M1.5): `.copy(...)` reproduces a symlink verbatim into `.build/<triple>/debug/tkzmux_<Target>.bundle/`, and because `.build/debug` is itself a symlink a relative target resolves one directory too high and dangles, so `Bundle.module` finds nothing under `swift test`/`swift run`. The same applies to individual files inside a copied directory, which is why `Shaders/TkzShaderTypes.h` is a real copy of the canonical header guarded by a byte-equality test rather than a link. `make app` therefore copies with **`cp -RL`** (dereferencing), or the `.app` gets dangling links. Wired: `TkzTerminalCore` → `terminfo`; `TkzTerminalRender` → `Fonts`, `Shaders`. Test fixtures live in `Tests/<T>Tests/Fixtures` (also `.copy`).
- **`Bundle.module` does not work inside a hand-built signed `.app`** (verified M1.9, all four variants tried). SwiftPM's generated accessor looks in exactly two places: `Bundle.main.bundleURL/<name>.bundle` — the **root** of the `.app`, not `Contents/Resources` — and an absolute `.build/…` fallback that masks the bug on the machine that built it. But `codesign --strict` rejects anything except `Contents` at an app-bundle root ("unsealed contents present in the bundle root"), confirmed for a bundle at the root, a symlink at the root, and a pre-signed bundle carrying its own `Info.plist`. The two rules are irreconcilable, so **app code must never evaluate `Bundle.module` inside an `.app`** — it traps. Each resource-bearing module therefore has a `ModuleResources.swift` that resolves through `Bundle.main.resourceURL` first (`Contents/Resources` in an `.app`, the executable's directory under `swift run`) and falls back to `Bundle.module` **last**, for `swift test` only. A fallback written *after* `Bundle.module` is dead code: it is a `static let` that `fatalError`s rather than returning nil, which is exactly the trap the original `bundledTerminfoDirectory` array literal fell into. `make app` is self-verifying (seven assertions after codesign, including "no unsealed contents at app root") and the launch smoke test hides the `.build` bundles so the `.app` cannot cheat.
- `Package.swift`: `platforms: [.macOS("26.0")]`; targets `GhosttyVt` (binary), `TkzPtyShim` (C), `TkzShaderTypes` (C header-only, shared Swift/Metal structs), `TkzTerminalCore` (depends on `GhosttyVt`), `TkzTerminalRender`, `TkzTerminalView`, `tkzmux` (exe), `tkzmux-vtdump` (exe), tests. Swift access to C: `GhosttyVt+Swift.swift` wraps handles as non-Sendable `final class`es with `deinit` frees (`GhosttyTerminalHandle`, `GhosttyRenderStateHandle`, `GhosttyKeyEncoderHandle`, `GhosttyMouseEncoderHandle`), `GhosttyError(result, operation)`, `GhosttyVtInfo` (version, build options, ABI manifest); `raw` pointers are `package`-visible for FrameBuilder.
- `make app`: `xcrun -sdk macosx metal -c Shaders/Terminal.metal -I Sources/TkzShaderTypes/include -o build/Terminal.air && xcrun metallib … -o tkzmux.app/Contents/Resources/default.metallib`; `swift build -c release`; copy binary, `Resources/terminfo`, `Info.plist`, SwiftPM resource bundles; `codesign --force --sign "$SIGN_IDENTITY"` (default `-`). `swift run`/tests fall back to `device.makeLibrary(source:)` from the `.metal` resource.

### Pty (`TkzPtyShim` C + `Pty.swift`)
- C only in the forked child (no Swift runtime after fork): `openpty(&m,&s,NULL,NULL,&ws)` → `fork()` → child `setsid()`, `ioctl(s, TIOCSCTTY, 0)`, `dup2`, reset signal mask/handlers, `chdir(cwd)`, `execve(path, argv, envp)`; exec failure reported via a `FD_CLOEXEC` pipe. Parent: `O_NONBLOCK|FD_CLOEXEC` on master. (Ghostty's own approach; posix_spawn can't do tty setup.)
- Spawn **zsh directly**: `path=/bin/zsh`, `argv=["-zsh","-l"]` (login semantics without `/usr/bin/login`, so env survives). Env from `TerminalEnvironment.make(sessionID:accountConfigDir:)`: `TERM=xterm-ghostty`, `TERM_PROGRAM=ghostty`, `TERM_PROGRAM_VERSION`, `COLORTERM=truecolor`, `TERMINFO=<bundle>/terminfo`, `LANG`, `ZDOTDIR=<tkzmux>/zsh`, `TKZMUX_ZDOTDIR`, `TKZMUX_USER_ZDOTDIR=$HOME`, `TKZMUX_BIN=<tkzmux>/bin`, `TKZMUX_SOCKET`, `TKZMUX_SESSION_ID`, `CLAUDE_CONFIG_DIR` (non-primary accounts only); remove `TERM_SESSION_ID`, `TERMINFO_DIRS`. **No PATH prepend** — the ZDOTDIR wrapper does it last (see Claude section).
- **Shim ABI 2.** `tkz_pty_spawn` is serialized by a static `pthread_mutex_t`: `fork()` duplicates the whole fd table, so a concurrent spawn between `openpty`/`pipe` and the `FD_CLOEXEC` `fcntl` would leak the *other* spawn's error-pipe write end and that spawn would then never see EOF and hang. Master and both pipe ends are `FD_CLOEXEC` before the fork. A failing `chdir` (stale worktree) does not fail the spawn — the child execs from the inherited cwd. A child that fails to exec is reaped inside the shim, so a failed spawn leaves no zombie and no fd.
- **Exit**: `DispatchSource.makeProcessSource(.exit)` + `waitpid(WNOHANG)`, plus an unconditional reap right after `resume()` — kqueue `NOTE_EXIT` never fires for a process that died between `fork()` and the registration. After reaping, the master is drained to EOF bounded to ~100 ms, so output written just before exit still arrives, but a slave held open by another process cannot stall it. The `WNOHANG` poll timer is a fallback that starts only *after* the pty has hung up: zero idle cost. The master fd is closed in exactly one place, the read source's cancel handler; the write source is always cancelled first.
- **`MAX_INPUT`**: a tty in canonical mode accepts only ~1 KiB per line; larger single lines are silently truncated. `TerminalSession`'s paste and `run(command:)` must chunk on **newlines**, not on byte count.
- API: `TerminalEnvironment.make(sessionID:accountConfigDir:tkzmuxDir:baseEnvironment:home:terminfoDirectory:)` (last three injectable, defaulting to the process env / `HOME` / the bundled terminfo) plus `loginShellSpawn(…) -> PtySpawn`; `bundledTerminfoDirectory` tries `Bundle.module` then `Bundle.main/Contents/Resources/terminfo`. `Pty.init(spawn:ioQueue:onData:onExit:)` takes its callbacks as **init parameters**, not settable properties, so nothing can arrive before there is a sink.
- `Pty`: read via `DispatchSource.makeReadSource(masterFD, queue: ioQueue)` draining ≤4×64 KiB per wakeup (`EIO` = EOF); writes only on `ioQueue`, `EAGAIN` → pending buffer + write source; `resize(TerminalSize{rows, cols, cellWidthPx, cellHeightPx})` → `TIOCSWINSZ` after `ghostty_terminal_resize`; exit via `DispatchSource.makeProcessSource(pid, .exit)` (kqueue) + `waitpid`; `foregroundProcess()` = `tcgetpgrp` + `proc_pidpath` + `PROC_PIDVNODEPATHINFO` cwd (no shell integration needed).

### VT bridge (`TerminalSession`)
- `ghostty_terminal_new(nil, &t, cols, rows)`; options via `ghostty_terminal_set`: `USERDATA`, `WRITE_PTY` (append to IO-thread-owned `pendingPtyOutput` — callbacks run synchronously inside `vt_write` and must not re-enter), `BELL`, `TITLE_CHANGED`, `PWD_CHANGED`, `CLIPBOARD_WRITE` (OSC 52 → NSPasteboard, reply SUCCESS; non-standard → UNSUPPORTED), `CLIPBOARD_READ` (DENIED), `DESKTOP_NOTIFICATION` (OSC 9/777/99 → sidebar badge + UNUserNotification when not visible), `PROGRESS_REPORT` (OSC 9;4), `COLOR_SCHEME` (DARK), `SIZE`, `XTVERSION` (`tkzmux <ver>`), `TERMINFO_NAME` (`xterm-ghostty`), `COLOR_FOREGROUND/BACKGROUND/CURSOR/PALETTE` (from theme; base 16 from theme, rest `ghostty_color_palette_default`), `SCROLLBACK_MAX_BYTES` (24 MiB — the library default is only **10 000 bytes**, verified, ≈557 rows at 120 cols, so this must always be set explicitly; NULL = unlimited), `CONTINUATION_MAX_BYTES` (4 KiB, and it must be set **before the first byte is written** or `ghostty_snapshot_encode_alloc` cannot capture an unfinished sequence), cursor style block/blink, `KITTY_IMAGE_STORAGE_LIMIT` small, `TITLE_REPORT` false, **`MODE_DEFAULT` 2027 on** (grapheme clustering defaults to *off* in the library; Ghostty's own app turns it on, and with it off a ZWJ family like `👨‍👩‍👧` splits into three double-width cell pairs that the renderer would have to shape per cell — see *Spike results (M1.3)* item 5). **`DEVICE_ATTRIBUTES` is deliberately not installed**: libghostty answers DA1 `ESC[?62;22c` and DA2 `ESC[>1;<ver>;0c` by itself (verified); a callback is only needed to advertise a different feature set. Installing `CLIPBOARD_READ` (we do, answering DENIED) also enables Kitty paste events (mode 5522).
- **Threading**: per session a serial `ioQueue` (`.userInteractive`) + a **`Mutex` (`import Synchronization`)** guarding the terminal and encoders. *(Corrected in M1 from `OSAllocatedUnfairLock`, which constrains its state to `Sendable` and therefore cannot hold the non-`Sendable` libghostty handles; `Mutex<State>` is `Sendable` for any `State`, so `TerminalSession` is `Sendable` with no `@unchecked`. Verified by compiling both under `-swift-version 6`.)* IO thread: `lock { ghostty_terminal_vt_write }` → flush pending pty output → publish events (`AsyncStream<TerminalEvent>` consumed on main) → `renderSignal` (`DispatchSourceUserDataOr` on main). Main: only marks `needsUpdate` and un-pauses the display link **if this session is visible**. Render tick: `lock { begin_update; end_update; iterate dirty rows into CPU row caches }`, GPU encode unlocked. Input: `lock { encoder setopt_from_terminal; encode }` → pty. C callbacks receive an `IOContext` as userdata, never the session, so a callback structurally *cannot* re-enter the lock; consumer closures run only after the lock is released. Background sessions: IO loop only, no render state, no display link, `ghostty_terminal_compress(INCREMENTAL)` from an idle timer (under the lock) — **measured to pay** (M1.10: 577 → 26 MiB footprint for 113 ms across 30 sessions). Schedule with `IdleCompressionPolicy`, drive the idle delay off `ghostty_terminal_compression_activity`, skip visible sessions, and **take the `.ghsnap` snapshot before compressing**, because reading history back rehydrates it. **Wired in M1.10**: `TerminalIdleCompressor` (in `TkzApp`) runs the policy from a `.utility` `DispatchSourceTimer` — 60 s idle threshold, 5 s tick, `stepInterval` 0 with a 4 096-step budget so a due session reaches `COMPLETE` inside one tick. Idleness is *polled* via `compression_activity` on the tick, never by instrumenting the pty read path. The token snapshotted at doubles as a dirty flag, so quit does not rehydrate what the timer just released (measured: quit sweep 58.8 ms for 30 files vs 8.1 ms for 1). Note `terminal.h` does not document whether a compression pass moves the activity token — **measured, it does not**, which is what makes that dirty-flag trick work.
- **Input seam.** Nothing outside `TkzTerminalCore` can obtain a `GhosttyTerminalHandle` (`withTerminal` yields the raw `GhosttyTerminal`, and `init(adopting:)` would double-free), so `KeyEncoder`, `MouseEncoder` and `SelectionController` live inside `SessionState` behind the session `Mutex` and are reached through public methods on `TerminalSession` (`encodeKey`, `pasteText`, `encodeMouse`, `mouseWheel`, `setMousePixelGeometry`, the `selection*` family, `copySelectionText`, `hyperlinkRun`). Each takes the lock, does the libghostty work, drops the lock, and only then runs a consumer closure — the same shape as `write(ptyBytes:)`.
  **Two directions, and confusing them doubles every paste**: key bytes and mouse reports are *returned to the caller* and written by the view layer; **paste bytes are written by libghostty itself** through WRITE_PTY, so `pasteText` harvests and delivers them like an ingested sequence and returns only a `PasteOutcome` — the caller must write nothing.
  `restore(from:)` swaps the terminal handle and `SelectionController` retains the handle it was built with (its `deinit` frees tracked grid refs against it), so **all three are rebuilt inside `restore(from:)` before the commit** — built after `applyOptions` succeeds and assigned with `state.terminal`, so a throw leaves the session wholly on its old state. Mouse geometry and the double-click interval persist across the swap. A controller held outside the lock would silently keep driving the discarded terminal.
  Selection changes and a non-tracking wheel scroll fire `renderSignal` after the lock drops; `encodeKey`/`encodeMouse` fire nothing, because nothing on screen changed. **`NSEvent.doubleClickInterval` must be pushed in** (`selectionDoubleClickInterval`) — `TkzTerminalCore` cannot read AppKit, and without it libghostty only ever sees single clicks.
  Measured through a live session: under Claude Code's `CSI > 5 u`, **Ctrl-C is `ESC[99;5u`, not `0x03`**, while Enter/Tab/Backspace keep their legacy bytes and Shift+Enter is `ESC[13;2u`. `PasteSource.text` suppresses only the Kitty paste event (mode 5522) — bracketing under 2004 still applies, so the IME path is framed exactly like ⌘V. Kitty flags survive a `.ghsnap` round trip.
- **DEC 2026**: libghostty-vt does **not** hide unsynchronized frames; Ghostty's renderer skips frames while mode 2026 is set and its IO thread resets it after 1 s. tkzmux: `ghostty_terminal_get(DATA_MODE, {mode: ghostty_mode_new(2026,false)})` per tick; active < 1 s → skip `begin_update`, keep link running; ≥ 1 s → force the mode off and render. **Verified (M1.3)**: with 2026 set, a write still leaves the render state `DIRTY_PARTIAL` and the formatter shows the new content — hiding frames is entirely the host's job. `DECRQM ?2026$p` answers `ESC[?2026;1$y` when set / `;2$y` when reset.
- **Snapshot**: `ghostty_snapshot_encode_alloc` under lock → `~/Library/Application Support/tkzmux/sessions/<id>.ghsnap` (lower `SCROLLBACK_MAX_BYTES` first to bound size); restore `ghostty_snapshot_decoder_new_buf` → `decoder_ready(&terminal)` (new terminal, renderable immediately) → re-apply options → decode history pages → spawn a fresh shell (old content + new prompt).

### Metal renderer (`TkzTerminalRender`)
- `FontSet` (CoreText only): **JetBrains Mono is bundled** (`Resources/Fonts/JetBrainsMono-{Regular,Bold,Italic,BoldItalic}.ttf` + `OFL.txt`; SIL OFL 1.1 permits redistribution inside an app carrying its license). `Info.plist` `ATSApplicationFontsPath = Fonts` registers them process-scoped at launch inside the `.app`; outside a bundle (`swift run`, tests) `FontSet` registers the same files from `Bundle.module` via `CTFontManagerRegisterFontsForURL(…, .process, …)` before resolving. The app-scoped copy wins over a differently-versioned system install, keeping cell metrics identical across machines. Menlo fallback; `CTFontCreateForString` per-scalar fallback cache; colour fonts via `kCTFontTraitColorGlyphs`. `CellMetrics` = max ASCII advance × round(ascent+descent+leading), underline/strike from CTFont, integer device px, rebuilt on backing-scale change.
- `GlyphRasterizer`: `CGBitmapContext` (8-bit alpha for grayscale, BGRA premultiplied for colour), `CTFontDrawGlyphs`, synthetic bold via fillStroke; wide graphemes get the 2-cell box. **`thicken`** (`Theme.Fonts.mono.thicken`, on; `tkzmux-vtdump atlas --thicken 0` to compare): CoreText font smoothing on the alpha-only context, which is not LCD filtering but a stem-darkening pass — Ghostty's `font-thicken` — worth ~17 % more coverage at 12.5 pt and one extra pixel of transparent padding for the dilation. Without it JetBrains Mono read as a lighter cut than cmux draws (side by side on a 1x display, 2026-09-08); the other two ingredients of that gap were size (cmux ran at 14 pt via the Ghostty config, ours is 12.5) and the dimmer `terminalForeground` token. `GraphemeShaper`: single scalar → `CTFontGetGlyphsForCharacters`; multi-scalar (ZWJ, VS16, combining) → `CTLine`/`CTRun`, cached. **No ligatures in v1.**
- `GlyphAtlas`: `r8Unorm` 2048² + `bgra8Unorm` 1024²→2048², shelf packer, batched `replace(region:)`, shared across sessions.
- `TerminalSurface` (only for the **visible** session): `ghostty_render_state_new`, row iterator, per-row caches of `TkzGlyphInstance`/`TkzRectInstance` + bg cell grid. Per tick: `begin_update/end_update`, `get(DIRTY)` (FULL → re-read COLS/ROWS/COLORS/CURSOR), `row_iterator_next_dirty` → `row_get(SELECTION)`, `row_cells_get_multi(RAW, STYLE, GRAPHEMES_LEN, HAS_STYLING)` — **`FG_COLOR`/`BG_COLOR` cannot be batched** (verified M1.5): they signal "unset" with `GHOSTTY_INVALID_VALUE` as the *result code*, and `row_cells_get_multi` stops at the first error, so a batch containing them aborts for almost every cell on screen; the two colours are fetched with individual `row_cells_get` calls, `ghostty_cell_get(WIDE / HAS_HYPERLINK)`; `BG_COLOR` returns `GHOSTTY_INVALID_VALUE` when unset → theme bg; bold-bright is app-side (verified not applied by the lib); then `render_state_clean`. **Cursor and selection are not free overlays** (verified M1.3, corrects the original assumption): a cursor move alone leaves `DIRTY_PARTIAL` with exactly the old and the new cursor row dirty — cheap, so the cursor may still be drawn as an overlay; but setting `OPT_SELECTION` leaves `DIRTY_FULL` and every row comes back from `row_iterator_next_dirty`, so a selection change costs a full row rebuild and the renderer cannot opt out. `FG_COLOR`/`BG_COLOR` do **not** resolve the inverse attribute (both return `GHOSTTY_INVALID_VALUE` for `ESC[7m` on an otherwise unstyled cell; `style.inverse` is true) and do not apply bold-brightening — both are app-side, and when both colours are unset the *defaults* are what get swapped. **SPACER_TAIL cells** (`WIDE == 2`) always report `GRAPHEMES_LEN == 0` and empty UTF-8 — the renderer must skip them, not draw a space. **Sized-struct ABI**: every libghostty struct with a `.size` field uses `MemoryLayout<T>.stride` (see spike row 15).
- **Per-cell resolution order and overlays (M1.5)**: fg = `FG_COLOR` else the render state's default foreground; bg = `BG_COLOR` else *nothing* (`TkzBgCell.color == 0`, which the shader composites to the theme background). Bold-brightening reads the palette index off `style.fg_color` and remaps 0–7 → 8–15; **inverse swaps afterwards**, so an unstyled `ESC[7m` cell swaps the defaults; `faint` drops the glyph alpha; `invisible` drops the glyph. The **selection is composited into the `TkzBgCell`**, never drawn as a rect — a selection change forces `DIRTY_FULL` anyway, so there is nothing to save. The **cursor is the one true overlay**: one `TkzRectInstance` built at flatten time (SOLID below the glyphs, HOLLOW above when unfocused), with `TKZ_GLYPH_FLAG_UNDER_CURSOR` stamped onto the covered glyph during flatten — so a blink or focus change costs one flatten and **no row rebuild**. Underline and strike coalesce into **per-run** rects so dotted/dashed patterns do not restart at each cell boundary. An atlas **rebuild** (not a regrow) invalidates every cached `atlasPos`, so the surface stamps the atlases' `rebuildGeneration` and forces a `DIRTY_FULL` second pass if it moves during a tick. A **backing-scale change means a new `FontSet` → new `GlyphCache` → new `TerminalRenderer`, and every surface must be re-attached.**
- Shaders (`TkzShaderTypes.h` shared structs `TkzUniforms`, `TkzBgCell`, `TkzGlyphInstance`, `TkzRectInstance`): bg full-screen pass sampling the cell grid; instanced rects (fill/hollow/underline single·double·curly·dotted·dashed/strike, procedural); instanced glyphs (gray = `rgb, a*tex.r`; colour = premultiplied). Order: bg → rects-below (block cursor, selection) → glyphs → rects-above (one rect pipeline, drawn twice). Entry points `tkz_{bg,rect,glyph}_{vertex,fragment}`; uniforms at buffer 0, instances at buffer 1, grayscale atlas at texture 0 and colour atlas at texture 1 (both always bound; one glyph pipeline branching on `TKZ_GLYPH_FLAG_COLOR`, since the branch is uniform per quad). Pixel space is device px, origin **top-left, +y down**; atlas coordinates are **texels** (`coord::pixel` sampler), so a 1024→2048 regrow cannot desync already-built instances. Instance colours are packed `uint32` **straight** sRGB (`r | g<<8 | b<<16 | a<<24`); every fragment function returns **premultiplied**. A `TkzBgCell` with alpha 0 means "no explicit background" and composites to the theme default — that is where `GHOSTTY_INVALID_VALUE` from `BG_COLOR` maps. `TkzShaderTypes.h` uses a classic include guard (never `#pragma once`) and `Terminal.metal` wraps its `#include` in `#if !defined(TKZ_SHADER_TYPES_H)`, because `device.makeLibrary(source:)` has no include search path and the loader concatenates the header text in front of the shader text. Layout is pinned by `_Static_assert`s that the C *and* both Metal compilers evaluate, mirrored by `MemoryLayout` assertions in the tests, so Swift, C and Metal cannot silently diverge. `.bgra8Unorm`, opaque layer, sRGB, 3-deep shared `MTLBuffer` ring + semaphore. **Dirty FALSE + no overlay change → no drawable acquired** (idle = zero GPU work).

### View & input (`TkzTerminalView`)
- The display-link decision is a **pure `DisplayLinkPolicy`** over a `DisplayLinkDemand` value (`needsUpdate`, `isDragging`, `hasSyncDeadline`, `isLiveResizing`, `isOccluded`, `hasVisibleSession`), so it unit-tests without a window; `DisplayLinkDriver` only owns the `CADisplayLink` and logs each pause/resume. **The cursor blink is an event, not a demand** — a 530 ms timer flips `TerminalSurface.cursorBlinkOn`, which marks the surface dirty and wakes the link for exactly one frame; modelling it as a demand would hold the link at 120 Hz forever. `show(session)` clears the *outgoing* session's `renderSignal` before installing one on the incoming session, so a background session structurally cannot wake the link (asserted by test: 50 writes to a background session produce zero signals and zero resumes).
- A backing-scale change goes through `TerminalRenderContext` (the app-wide `FontSet` → `GlyphCache` → `TerminalRenderer` owner plus a weak registry of live surfaces): new font set, new atlases, new renderer, **re-attach every registered surface**, then re-derive the grid — new metrics fit a different number of cells. A drawable-size change with an unchanged grid still marks the surface dirty, or Core Animation stretches the previous texture over the new bounds.
- **`presentsWithTransaction`**: `MTLCommandBuffer.present` schedules an asynchronous present *outside* the Core Animation transaction, which is the tearing the live-resize path exists to avoid. `TerminalRenderer.render(surface:layer:)` therefore reads `layer.presentsWithTransaction` itself and does the `waitUntilScheduled()` + `drawable.present()` handshake internally, acquiring the drawable **after** the skip check so the idle guarantee holds on the resize path too.
- `RenderSignalRelay` coalesces a session's IO-queue `renderSignal` into at most one in-flight main-thread hop (a busy `cat` signals thousands of times per frame otherwise). `CADisplayLink` retains its target, so a terminal view must be removed from its window before being dropped.
- The cursor on a **SPACER_TAIL** cell spans both cells with its origin shifted one column left, or the block sits on the right half of a CJK character and hides nothing that is there.
- `TerminalMetalView: NSView, NSTextInputClient`; `makeBackingLayer → CAMetalLayer` (`displaySyncEnabled`, `maximumDrawableCount = 2`, `framebufferOnly`); `NSView.displayLink(target:selector:)` paused unless `needsUpdate` / blink / drag / 2026 deadline; `preferredFrameRateRange` 60…120; occlusion pauses; `presentsWithTransaction` only during live resize (commit → `waitUntilScheduled` → `present`). `show(session)` detaches the previous `TerminalSurface` and attaches a new one (FULL rebuild); one `TerminalRenderer` (pipelines, atlases, buffers) app-wide.
- **Keyboard**: IME first (`inputContext.handleEvent`; marked text = preedit overlay), then a `KeyPress` (`TkzTerminalCore/KeyEncoder.swift` — deliberately in **Core, not View**, so the whole encoding path unit-tests without AppKit): action, physical key via `MacKeyCodes.swift` (a from-scratch macOS `kVK_*` → `GhosttyKey` table cross-checked against Ghostty's `keycodes.zig`, no AppKit import), mods incl. side bits from the `NX_DEVICER*KEYMASK` raw flags, utf8 filtered of C0/DEL/PUA U+F700–F8FF, unshifted codepoint from `characters(byApplyingModifiers: [])`, consumed mods, composing → `lock { ghostty_key_encoder_setopt_from_terminal; re-set MACOS_OPTION_AS_ALT (setopt_from_terminal resets it — documented in key/encoder.h); encode }` → pty. **Option-as-alt needs the view's help** (verified M1.7): libghostty computes `effectiveMods = mods − consumedMods` whenever text is non-empty, so building the press the obvious way (text `∫`, Option consumed) encodes `∫` even with `MACOS_OPTION_AS_ALT` set. When Option acts as Alt the view must translate the key *without* Option (text `"b"`, Option left **unconsumed**) — Ghostty does this via `ghostty_surface_key_translation_mods`, which libghostty-vt does not export, so `KeyEncoder.translationModifiers(for:optionAsAlt:)` reimplements it. The full encoding matrix is **generated** into `docs/keys.md` by the tests and asserted on every run, so it cannot drift. `keyUp` → RELEASE, `flagsChanged` → modifier press/release, `performKeyEquivalent` lets ⌘-shortcuts through to the app, `doCommand(by:)` no-op. Non-keyDown text (emoji picker, dictation) → `ghostty_terminal_paste(source: TEXT)`.
- **Mouse**: tracking area; if `DATA_MOUSE_TRACKING` and no Shift → `GhosttyMouseEvent` → `ghostty_mouse_encoder_encode` (options synced via `setopt_from_terminal`, size via `OPT_SIZE`); else selection via `GhosttySelectionGesture` (PRESS/DRAG/RELEASE, CELL/WORD/LINE behaviours, Option = rectangle, autoscroll ticks) → `ghostty_terminal_set(OPT_SELECTION)`. Copy = `ghostty_terminal_selection_format_alloc` (PLAIN, unwrap, trim). Wheel: tracking on → one *press* report per row, button four (up) / five (down) — measured SGR bytes `ESC[<64;col;rowM` up, `ESC[<65;col;rowM` down, and a wheel notch sends **only the press**; off → `ghostty_terminal_scroll_viewport(DELTA)` (up is negative), with fractional trackpad deltas accumulated into whole rows by `ScrollAccumulator`. `setopt_from_terminal` syncs only tracking mode and format — `OPT_SIZE` and `OPT_ANY_BUTTON_PRESSED` are the embedder's, so `MouseEncoder` tracks held buttons itself and a motion event must carry the **held** button or drags are silent under mode 1002. A drag includes the cell under the pointer only past its horizontal midpoint, so the view must pass **real pointer pixels**, never a re-centred cell coordinate. Paste = `ghostty_terminal_paste` (bracketed + chunking inside the lib) after `ghostty_paste_is_safe` (confirm sheet if unsafe). OSC 8: hover with ⌘ → `ghostty_terminal_grid_ref` + `ghostty_grid_ref_hyperlink_uri` → pointing-hand + underline overlay, ⌘-click opens. Focus in/out → `ghostty_focus_encode` when mode 1004; hollow cursor when unfocused.

### TerminalHost — the seam between halves (protocol in `TkzApp`)
```swift
protocol TerminalHost: AnyObject {
  func open(_ id: SessionID, cwd: String, env: [String: String], size: TerminalSize) throws -> pid_t   // shell pid
  func run(_ id: SessionID, command: String)          // types command + "\r"
  func runWhenReady(_ id: SessionID, command: String) // same, once the shell is ready (M2.5)
  func show(_ id: SessionID?)                          // attach the single renderer; nil = none
  func resize(_ id: SessionID, _ size: TerminalSize)
  func close(_ id: SessionID, signal: Int32)           // SIGHUP default; row stays resumable
  func snapshot(_ id: SessionID) throws -> Data        // .ghsnap of the live grid
  func restore(_ id: SessionID, from: Data, cwd: String, env: [String: String]) throws -> pid_t  // replaces a held id
  func savedSnapshot(_ id: SessionID) -> Data?         // the .ghsnap on disk (M5.2)
  func discard(_ id: SessionID)                        // Remove: hang up, drop the grid, delete the snapshot (M5.2)
  var events: AsyncStream<(SessionID, TerminalEvent)> { get }
    // .title(String) .pwd(String) .bell .notification(title, body) .progress(state, value) .exited(ExitStatus) .foreground(pgid, path?, cwd?)
}
```
The protocol is **`@MainActor`**: the implementation (`TerminalViewHost`) owns the `TerminalMetalView`, and a nonisolated protocol cannot be conformed to by a main-actor class under Swift 6 strict concurrency.

`close` keeps the row resumable, so nothing in the original protocol could *remove* a session. The implementation added a non-protocol `discard(_ id:)` that cancels the event pump, hangs up the shell, forgets the row and deletes its `.ghsnap` — without it **a closed tab resurrects on every launch**, because restore-on-launch reads the whole snapshot directory. **M5.2 put `discard` and `savedSnapshot` in the protocol** (the window's Remove and its lazy reopen need them through `any TerminalHost`), made `discard` delete the snapshot *whether or not the host holds the session* (a restored row that was never shown has a file and no `HostSession`), and made `open`/`restore` **evict** a session the host already holds under that id — a ⌘W'd row keeps its dead grid attached until it is reopened, and adopting over it used to append the id to `order` twice and leave the old event pump running. **`TerminalViewHost` creates `<tkzmuxDirectory>/zsh` on init** (M2.5): `make` points every session's `ZDOTDIR` there unconditionally, and before M3.3 wrote the wrapper rc files nothing created it — so every login zsh failed to lock `.zsh_history` and printed the failure *into the user's terminal*, most visibly on SIGHUP. An empty directory was the correct intermediate state: zsh still finds no rc files. **M2.5 decided it does not** (TKZ-43): `close` keeps a row resumable and that is all the window needs; *removing* a session is M5.2's verb, and the callers that need `discard` (`shutdown`, and restore housekeeping later) already hold the concrete host. `SessionID` lives in `TerminalHost.swift` for now, validated against `SnapshotStore.isValidSessionID` (a session id is also a file basename and `TKZMUX_SESSION_ID`); **M2 moves it to `TkzCore` with the real `Session` model**.

`run(_:command:)` chunks on newlines (`MAX_INPUT` ≈ 1 KiB, M1.2); a single longer line is still truncated by the tty. **It must not be called in the same turn as `open`** — a login zsh calls `tcsetattr(…, TCSAFLUSH, …)` while setting up its line editor, which *discards whatever is already in the tty input queue*. Measured: with no delay the command is silently swallowed and never runs. **Settled in M2.5** (TKZ-43): the readiness signal is *first child output, then quiet for 150 ms*, implemented as `Pty.writeWhenReady(_:settle:timeout:)` in `TkzTerminalCore` — a bare login zsh's first bytes are its prompt, printed after ZLE is up. The settle window is re-armed by every further chunk (so a still-spewing child is not typed into mid-burst) and a 2 s outer timeout covers a child that prints nothing at all. There is no prompt marker to trigger on instead: the ZDOTDIR wrappers are M3.3's, so today's shells source no rc files. `TerminalHost.runWhenReady` is a **protocol requirement**, not an extension-only method: `MainWindowController` holds `any TerminalHost`, and a call to an extension-only method on an existential is statically dispatched and would never reach `TerminalViewHost`. The 2 s delay survives only as the protocol extension's default, for test doubles. **Scope correction (M2.5):** the M1.10 loss is not a property of every spawn — a same-turn write to a *single* hermetic login zsh reliably runs (measured three times out of three in `PtyTests`). M1.10 measured 30 simultaneous spawns under the full environment. So `writeWhenReady` is the right thing to depend on, but the mirror-image "it is always swallowed" control is deliberately not asserted anywhere: it is a claim about timing under load, not an invariant.

**A bad `cwd` does not fail the spawn.** `tkz_pty_spawn` runs `chdir` after `fork()`, where there is nothing safe to report through, and ignores its return value — the shell simply starts in the inherited directory and `open` returns a valid pid. Validating the directory is therefore the *launcher's* job (`MainWindowController.launch`), and so is tilde expansion: the models keep paths as written (`Group.repoRoot`, `Session.cwd`, `Launch.cwd`), and `Paths.expandingTilde` is applied once, at the boundary where a path becomes a `chdir` argument.

**Anything that must render headlessly has to be a `CALayer`, not an `NSView`** (learned in M2.3): a subview's backing layer is not grafted into its superview's layer tree until the hierarchy reaches a window, so `CALayer.render(in:)` on a windowless view silently omits every subview — the first sidebar rows rendered with no status dot and no `＋`. `NSView.cacheDisplay(in:to:)` is not an alternative; it does not capture custom sublayer properties either. The sidebar rows therefore draw entirely in layers, with an invisible `NSButton` over the `＋` purely for hit-testing.

`.tkzrec` v1 = one line of JSON (`magic`, `version`, `cols`, `rows`, `argv`, `env` summary, `startedAt`, `note`) followed by binary frames `[u8 kind][u64 LE elapsedNanos][u32 LE len][payload]`; kind 0 = pty output, 1 = resize (u16 cols, u16 rows), 2 = host input. Unknown kinds are skipped by length and a truncated final frame is tolerated (a recording ends when the session is killed). `head -1 f | jq` inspects it; writer/reader in `TkzTerminalCore/Recording.swift`. `tkzmux-vtdump record --out X.tkzrec [--cols N --rows M] [--cwd D] [--script F] [--golden G] [--note T] [--timeout MS] [--quiet] [--inherit-env] -- <cmd>` spawns `<cmd>` on a pty under the full `TerminalEnvironment` and tees every byte in. The child gets a **minimal** base env (`HOME`, `PATH`, `SHELL`, `USER`, `LOGNAME`, `TMPDIR`, `LANG`) plus the tkzmux contract, so a recording is reproducible and cannot carry the recorder's environment (`--inherit-env` opts out); the header stores only the five VT-relevant variables, asserted by a test. A `--script` file drives the child: `wait <ms>`, `waitfor "<text>" [<ms>]` (polls the rendered screen), `send "<text>"` (escapes decoded, chunked at newlines because a canonical-mode tty truncates past `MAX_INPUT`), `resize <cols> <rows>`, and `stop` — **SIGKILL, deliberately**: ending with SIGHUP lets Claude Code tear down cleanly and the fixture then records every mode being *reset*, which is a correct recording of a useless fact. - **Startup state** (M2.5): the app comes up on `AppState.startup(homeDirectory:)` — one group rooted at the user's home directory, no sessions, no selection. The group carries `repoRoot = home` rather than the `nil` of a bucket because `NewSessionMenu` disables every launch row without one; home is not a repo, so *New worktree* is enabled there and fails when picked; real repo groups come from *＋ New group* and *In another repo…* (M5.2). `AppState.fixture` — 40 fabricated, deliberately unlaunchable rows — moved behind `TKZMUX_FIXTURE=1`, where the M2.3/M2.4 artboard comparisons still use it. The toolbar's `>_` ("new terminal") is the one launch that needs neither a repo nor `claude`: `Launch.Kind.shell` opens a login shell and types nothing.
- **Store**: `AppStore` (`@MainActor`) owns `AppState` (groups, sessions, accounts, usage, selection, sidebarVisible, windowFrame, presets, shortcuts). `store.update { … }` diffs into `ChangeSet {sessions, groups, structure, selection, usage, chrome}` delivered once per run-loop turn by a main-queue `DispatchSource.makeUserDataAddSource`. **Granularity is the point**: `sessions`/`groups` name the ids whose value differs; `structure` is set **only** when the id set changes, a session's `groupID` changes, or an `order` changes — a Claude status flip, a rename, a git refresh or a group collapse must not set it, so the sidebar reloads one row rather than forty. `chrome` (added in M2.1 beyond the original five) covers `sidebarVisible`, `windowFrame`, `presets` and `shortcuts`, which no row depends on: without it those mutations diffed to empty and were **never delivered**, and `sidebarVisible` was wrongly forcing `structure`. `pending` is reset before observers run, so an `update` from inside an observer arms the next turn rather than being swallowed; **never call `update` from inside a `mutate` closure** (exclusivity trap). Services run on their own queues/actors and post into the store; they never touch views. No `@Observable` (row-granular reloads need explicit change sets).

## Claude integration (ClaudeBridge)

- **Accounts are generic** (decision 2026-09-08): `~/.claude` is the only given. No second account, path or label is ever hard-coded — the app is meant to be shared, and only this machine has two config dirs. **Today the app knows only `~/.claude`**: `ClaudeIntegration` watches `~/.claude` plus the `configDir` of every `Account` in the store, and nothing puts an account there yet (accounts are not persisted, and the discovery that was sketched for M3.5 — every `~/.claude-*` directory carrying `settings.json`, `sessions/` or `.claude.json`, labelled from the `dash-accounts.json` overlay — is backlog with TKZ-25). How a second account gets in (that discovery, or a settings entry) is an open decision.
- **Discovery**: watch `<configDir>/sessions` for every discovered account with a directory `DispatchSource` (add/remove) **and** a per-file `DispatchSource` (`.write|.extend|.delete|.rename|.attrib`) since descriptors are rewritten in place; 100 ms debounce; torn JSON keeps the previous value; liveness 5 s `kill(pid,0)`; pid-reuse guard `proc_pidinfo(PROC_PIDTBSDINFO).pbi_start_tvsec` vs `startedAt`; show `kind=="interactive"`, attach `bg` to its parent via `parkedJobId==jobId`. Idle cost ≈ 40 syscalls / 5 s. Implemented as `ClaudeBridge/ClaudeSessionWatcher.swift` + `ProcessLiveness.swift` (M3.1): state behind a `Mutex`, sources on a private serial queue, `onEvent` `.updated(info, alive:)` / `.removed(key)` in order, `snapshot()` lock-only so it is safe from inside a callback (`start`/`stop`/`setConfigDirs` are not — they `queue.sync`). **Measured 2026-09-08**: an in-place `O_TRUNC` rewrite fires `.attrib` then `.write|.extend`; a rename-replace fires **`.delete` on the watched inode, never `.rename`** (`NOTE_RENAME` is for the watched vnode being renamed, not for something renamed over its path), so `.delete` is the signal to re-stat and reopen. End-to-end latency of an in-place edit ≈ 60 ms at a 30 ms debounce. Fds are closed only in their source's cancel handler — cancellation is asynchronous and a synchronous close races a still-registered kqueue on a reused fd number. `proc_listchildpids` ignores the size-query idiom (`NULL, 0` returns a bogus system-wide count) and returns a **pid count**, not bytes; `ProcessTree.children(of:)` uses a fixed 4096-entry buffer. `sh -c 'sleep 30'` execs `sleep` in place of the shell — a trailing `; true` is what makes a real child for tests.
- **Account key**: the basename of the config dir minus its leading dot (`~/.claude` → `claude`, `~/.claude-alt` → `claude-alt`) — the same spelling as `Account.key`, `Session.accountKey` and `dash-usage-<key>.json`, so descriptor→session joins on it.
- **Identity**: the shim `exec`s the real `claude`, so the shim's `$$` **is** the descriptor pid; it sends a `launch` frame `{sid, pid, cwd, config_dir, argv}` first, so `pid → SessionID` is known before `<pid>.json` exists. Fallback: `proc_listchildpids` walk from the shell pid. `--session-id` not used; latest `sessionId` recorded for `--resume`. **Implemented in `TkzApp/ClaudeIntegration.swift`** (M3): the coordinator owns `pidToSession` (the `launch` bindings) and joins in this order — a hook frame: `sid` → a row with that `claudeSessionId` → walk `ppid` up (≤ 8 levels) to a bound `claude` pid or a session's shell pid; a descriptor: `launch` binding → a row already carrying the pid → a row with the same `claudeSessionId` and no descriptor (a resume) → the parent walk from the descriptor pid. A descriptor nothing claims is kept in `externalDescriptors` for M5.3's Elsewhere group. Every service callback is hopped to the main queue with `DispatchQueue.main.async` (FIFO), never an unstructured `Task`, so two frames from one session apply in arrival order. The `launch` frame can lose the race against the 100 ms descriptor debounce, so binding a pid also re-applies any descriptor the watcher already holds for it. Only rows with live state are attribution targets: a restored row has no shell, and a `claudeSessionId` reused by a resume elsewhere must not resurrect it. **Verified end to end 2026-09-08** with the built app running and a real `claude` started through the installed wrappers on a pty: `log stream` (category `claude`) showed the watcher's initial scan reporting the two Claude sessions already running elsewhere, the shim's `launch` frame with the new pid, and the `SessionStart` hook 0.85 s later carrying the same `TKZMUX_SESSION_ID`. Attribution to a row needs the GUI (a session launched from the sidebar) and is on the manual checklist.
- **Status derivation** (first match): not alive → `exited` (the *terminal* is gone — the scrim, hollow dot and suppressed cursor all mean that); SessionEnd(reason ∉ clear,resume) → `idle` (Claude quit, the shell is a plain terminal again; **not** `exited` — reported 2026-09-08: Ctrl-C twice left the row "Exited" and the screen dimmed while the prompt was alive and taking input); pending permission_prompt|elicitation → `waiting(.permission/.elicitation)`; agent_needs_input → `waiting(.agentInput)`; **descriptor `status == "waiting"` → `waiting(.permission)`** (see below); `parkedJobId` → `idle` (parked); descriptor `busy` → `working`; Stop newer than `attendedAt` and (idle_prompt or ≥60 s) → `waiting(.doneUnattended)` = NEEDS YOU; Stop <60 s → idle “done”, drawn as `SidebarStatus.done` — the accent-coloured dot, no pulse — so a finished answer is visible before it ages into NEEDS YOU (GUI pass 2026-09-08: green straight to grey read as nothing having happened); else `idle`. Pending clears on UserPromptSubmit/Stop/SessionEnd/elicitation_complete/descriptor busy newer than the notification. Degrades to descriptor-only without hooks. Implemented in `TkzCore/StatusDerivation.swift` (pure, `StatusInput → StatusOutcome {status, attention, isDone}`) and the reducers `applyHook` / `applyDescriptor` / `descriptorLost` / `setAlive` / `rederiveStatuses` (M3.4); `ClaudeIntegration` re-runs `rederiveStatuses` every 5 s for the 60 s rule. SessionEnd `reason` vocabulary per the hooks docs: `clear`, `resume`, `logout`, `prompt_input_exit`, `other`; only `clear` and `resume` are *not* an exit, and a missing reason counts as one. **`attendedAt` moves only on select, on UserPromptSubmit, when the window becomes key with a row selected, and when a Stop lands on the selected row of a key, unoccluded window** — without the last one the session the user is watching would age into NEEDS YOU under their nose.
  **Measured 2026-09-08** (Claude Code 2.1.263, interactive session on a pty driven by `tkzmux-vtdump record --script`, hooks logged with timestamps, descriptor polled every 200 ms): the descriptor is written ~200 ms after start as `idle`; `busy` on prompt submit; **`waiting`** while the permission prompt is on screen (a third status the ticket did not know about — `ClaudeSessionInfo.Status.waiting`), `busy` again 40 ms after it is answered, `idle` 8 ms after the Stop hook. The `permission_prompt` Notification fired 15 ms before the descriptor flipped to `waiting`, with payload `{session_id, transcript_path, cwd, scratchpad_dir, prompt_id, hook_event_name, message: "Claude needs your permission", notification_type}` — no pid, so attribution is `sid` → `session_id` → `ppid`. It fires whether or not the terminal is "focused": a pty has no focus, so the badge also lights on the row the user is looking at, which is the intended reading (the amber says *answer this*). Answering clears it through the existing rule (descriptor `busy` with `statusUpdatedAt` newer than the notification); `PostToolUse` fired 0.7 s after the answer and is not needed. Without hooks the `waiting` descriptor status alone yields NEEDS YOU for prompts.
- **Titles**: user rename → descriptor `name` when `nameSource != "derived"` → worktree name → `basename(cwd)`, where the cwd is **Claude's** (`descriptor.cwd`) once a descriptor is bound and the shell's starting directory before (GUI pass 2026-09-08: a shell opened in the home group and `cd`'d into a repo kept the home name). A fresh session's descriptor `name` is `derived` (`<dir>-<2 hex>`) and only becomes `auto` once Claude names it, which took about two hours on a real session — so "titles update when Claude auto-names" is a slow test. ⇧⌘R is a sheet with a text field (empty = back to the derived title); it had been in the menu since M2.4 with no handler.
- **Shim install** at `~/Library/Application Support/tkzmux/{bin/claude, bin/tkzmux-hook, zsh/…, tkzmux.sock, state.json, sessions/, VERSION}`, idempotent, never touches `~/.claude/settings.json`. **ZDOTDIR wrapper** (the single mechanism; no PATH prepend from the pty): each wrapper sources the user's file with `ZDOTDIR` restored, `.zshrc` ends by putting `$TKZMUX_BIN` first on `path` exactly once, `.zlogin` restores `ZDOTDIR` for nested shells (unset when the user had none). zsh only. Implemented (M3.3): the wrapper sources live in `Sources/ClaudeBridge/Resources/zsh/{zshenv,zprofile,zshrc,zlogin}` **without the leading dot** (SwiftPM resource copying of dotfiles is not relied on) and `ShimInstaller` writes them dotted; every wrapper is a no-op unless both `TKZMUX_ZDOTDIR` and `TKZMUX_USER_ZDOTDIR` are set; a user rc that relocates `ZDOTDIR` (`~/.config/zsh`) is followed for the later wrappers. **`/etc/zshrc` sets `HISTFILE=${ZDOTDIR:-$HOME}/.zsh_history` before the user's rc runs**, i.e. into our directory, so `.zshrc` points a HISTFILE that still equals ours back at `$TKZMUX_USER_ZDOTDIR/.zsh_history` (a HISTFILE the user set is left alone). Verified: `zsh -l -i -c` on zsh 5.9 sources all four files in order. `VERSION` is a SHA-256 over the shim, the four wrappers and the hook binary's size+mtime, so idempotence is content-based and never needs a bump; `remove()` deletes only `bin/`, `zsh/` and `VERSION`. `make app` builds `tkzmux-hook` as a second product and copies it to `Contents/MacOS/` next to `tkzmux`, which is also where `swift run` finds it (`ShimInstaller.standardHookBinary()`); the installer then copies it into `bin/`. The menu carries *Remove Shell Integration* (no key).
- **Shim** (`bin/claude`, bash): find real `claude` skipping `$TKZMUX_BIN`; pass through for subcommands, `-p`, `--bare`, `--safe-mode`, `-v`, `-h`, or unset `TKZMUX_SESSION_ID`/`TKZMUX_SOCKET`; strip user `--settings`, deep-merge via `tkzmux-hook settings-merge` (hook arrays concatenated, user first; failure → exec untouched); `tkzmux-hook launch`; `exec real … --settings <merged>`. Injected hooks: SessionStart, SessionEnd (timeout 1), UserPromptSubmit, Stop, Notification (matcher `permission_prompt|idle_prompt|elicitation_dialog|elicitation_url_dialog|elicitation_complete|elicitation_response|agent_needs_input`) → `"<bin>/tkzmux-hook <Event>"`. **`--settings` twice: the last one wins, hooks included** (measured 2026-09-08 with two SessionStart hooks touching different files — only the second ran), which is exactly why the shim strips the user's `--settings` and merges rather than appending its own. `--settings` accepts a JSON *string* as well as a path (`claude --help`: `<file-or-json>`), so `settings-merge` prints the merged document to stdout and the shim passes it inline — no temp file. The hooks template lives in the hook binary, not the shim. Pass-through subcommand list from `claude --help` 2.1.263: `agents attach auth auto-mode doctor gateway import install logs mcp plugin plugins project respawn rm setup-token stop kill ultrareview update upgrade`. `/bin/bash` is 3.2, where `"${arr[@]}"` on an empty array is an unbound-variable error under `set -u` — the shim uses `"${args[@]+"${args[@]}"}"`. The shim skips itself both by PATH entry (literal or realpath-equal to `$TKZMUX_BIN`) and by candidate realpath, so a duplicated or symlinked bin dir cannot make it exec itself.
- **`tkzmux-hook`** (< 20 ms, `import Darwin`): stdin → single line → `AF_UNIX` connect, 200 ms poll → one NDJSON frame `{"v":1,"type":"hook","event","sid","ppid","ts","payload"}` → exit 0 on every path, never writes stdout. App: POSIX listener + DispatchSource, 256 KiB frame cap, keeps 4 KiB of `last_assistant_message` for UI; attribution `sid` → `payload.session_id` → pid tree. Implemented (M3.2) as `Sources/tkzmux-hook/{main,StdinReader,Json,HookFrameBuilder,Socket,LaunchCommand,SettingsMerge,Debug}.swift` (a hygiene test keeps every file at `import Darwin`) and `ClaudeBridge/{HookFrame,HookServer}.swift`. Modes: `tkzmux-hook <Event>`, `tkzmux-hook launch --pid N --cwd D -- argv…` (`config_dir` = `$CLAUDE_CONFIG_DIR` else `$HOME/.claude`), `tkzmux-hook settings-merge [path-or-json]` (merged JSON on stdout; the only mode that writes stdout; exit 1 and nothing on stdout when the user document is unusable, which the shim turns into an untouched exec). **Measured 2026-09-08: 4–5 ms median, debug or release, app up, down or socket path nonexistent** — the floor is fork/exec + dyld, not the binary. Size policy: stdin capped at 1 MiB; a frame over 240 KiB has every JSON string over 64 KiB cut (state machine over quotes and escapes, on a UTF-8 boundary, `…[truncated]` appended); stdin that hit the cap goes out as `{"truncated":true}`; empty stdin → `payload: null` so the envelope stays valid JSON. `HookServer` hands `.hook(HookEvent, ppid:, fullMessage:, cwd:)` / `.launch(LaunchAnnouncement)` to one `@Sendable` closure on its queue in arrival order (a closure, not an `AsyncStream` — single-consumer streams have bitten this codebase before); a connection whose unterminated buffer passes 256 KiB is dropped; a stale socket file is unlinked only after a failed `connect`. The docs' `SessionStart` stdin list does not show `source` (only as a matcher value `startup|resume|clear|compact|fork`); it is mapped when present. Two Swift 6 workarounds worth reusing: a `Mutex<State>` cannot hold a class with `DispatchSource` fields (`inout sending` region error) — keep the per-connection state a `Sendable` struct, as `Pty.State` does; and `indirect enum JSONValue { case object([(String, JSONValue)]) }` crashes the compiler with a circular-reference error — use a named pair struct. `sun_path` is 104 bytes: socket tests use `mkdtemp("/tmp/tkzhs.XXXXXX")`, never the long scratchpad path.
- **Usage** (M3.5 / TKZ-25 — **backlog, not built**; the status bar's `Context`, model badge and `Usage` segments stay empty until it is): `UsageReader` watches `~/.claude/dash-usage-*.json` (key = filename), overlay `dash-accounts.json`; reconcile ported verbatim from `quota-parser.ts` (dead-window guard, high-water keyed on `resets_at`, 10-min confirmation TTL, 14-day ghost) with the mac-dash scenarios as tests. Status bar shows `seven_day` for the selected session's account.
- **Per-session sidecar (tkzmux-owned contract)**: `~/.claude/dash-sessions/<session_id>.json` = `{updated_at, session_id, account_key, context_used_percentage, model{id,display_name}, session_name, workspace{git_worktree,project_dir,repo}, worktree?, pr{number,url,review_state}?, cost}`. Producer today: **edit the mac-dash source** `~/dev/mac-dash/scripts/statusline-capture.js` (add `writeSessionSidecar` after `writeSnapshot`, same throttle/tmp+rename/try-catch) and `npm run install:statusline` (the `~/.claude` copy is generated). Later: a `tkzmux-statusline` wrapper for other users. Join on `descriptor.sessionId`; ignore sidecars > 24 h; housekeeping deletes > 7 d.

## Git integration (GitStatus)

- Repo detection per cwd: `git -C <cwd> rev-parse --show-toplevel --git-dir --git-common-dir --abbrev-ref HEAD`; `repoRoot = parent(common-dir)`; `isWorktree = realpath(git-dir) != realpath(common-dir)`.
- Always `--no-optional-locks` / `GIT_OPTIONAL_LOCKS=0`: `status --porcelain=v2 --branch -z` (branch, upstream, `branch.ab`, changed/untracked) and `diff HEAD --shortstat` (~22 ms on CoreInvest). No auto-fetch (optional 10-min pref, off).
- Triggers: one `FSEventStream` per repoRoot (common-dir + session cwds; ignore `.git/objects`, `node_modules`), 300 ms debounce, ≤1/2 s in bursts; after each Stop hook; on selection if >10 s old. Per-repo serial queue; rows re-render only on `GitSummary` change.
- PR: sidecar `pr.*` first; `gh pr view --json number,state,url,isDraft,reviewDecision` only for github.com origins (CoreInvest = Azure DevOps → never), selected session only, throttled, failures cached 10 min.
- Ports via **libproc**: `proc_listchildpids` from the shell pid → `proc_pidinfo(PROC_PIDLISTFDS)` → `proc_pidfdinfo(PROC_PIDFDSOCKETINFO)` → `SOCKINFO_TCP && TSI_S_LISTEN` → `ntohs(insi_lport)`; selected session on selection, after Stop, 10 s timer. (lsof = 30–70 ms + fork; rejected.)

## Session flows & persistence

Start: create `Session` (persist) → `TerminalHost.open` → `run(command)` → shim `launch` binds pid → descriptor appears → SessionStart confirms `claudeSessionId`. Implemented in **`TkzApp/SessionLauncher.swift`** (M5.2): `start(spec)`, `reopen(id)`, `resume(id)`, `resumeAll`, `close(id)`, `remove(id)`, `noteExit(id)`; `MainWindowController` only routes menus, confirmations and notices to it. Every start/reopen writes one line to the unified log, category `launch`, with cwd, `CLAUDE_CONFIG_DIR` and the command (docs/perf.md → *Launch audit*).
- **New worktree** (cwd = repoRoot, `claude -w [name]`; the descriptor's cwd is `<repo>/.claude/worktrees/<name>` because Claude starts *inside* the worktree it created, so `applyDescriptor` sets `worktreePath`/`isWorktree` from it — `Session.worktreeRoot(ofPath:)` — and the row's title becomes the worktree name until Claude names it). No name sheet: a named worktree is a preset with `cwdMode: worktree(name)`. **Repo root** (`claude`). **Another repo…** (`NSOpenPanel` → `createGroup(from:)`, which dedupes on `repoRoot` → the repo-root launch in that group; the palette's group rows are the "known repos" half). **Preset** `{name, command, cwdMode: repoRoot|worktree(name?)|fixed(path), accountKey?, env}`; `Launch.env` carries `Preset.env` over the account's `CLAUDE_CONFIG_DIR` (a preset may override it, on purpose). CRUD is `PresetsSheetController` ("Manage presets…", in the presets submenu and the app menu): edits a copy, commits the whole list on Done; `PresetDraft` is the pure, tested half (`KEY=VALUE` env lines, per-mode argument, named problems).
- **The account follows the session, not the store's account table.** Accounts are rediscovered, never persisted, and today nothing discovers a second one — so after a relaunch every non-primary row names an account the store has never heard of. `SessionLauncher.configDirectory(forKey:)` uses the store's `configDir` when the account is known and otherwise **derives `~/.<key>`**, the inverse of the account-key rule (`Account.configDirectory(forKey:home:)`); only the primary key means "leave `CLAUDE_CONFIG_DIR` unset". Without this every restored second-account row resumed on the primary account, the one failure TKZ-30 singles out.
- **Restore** (rows in M5.1, content in M5.2): a restored row exists in the store with **no terminal behind it**, so the window's empty state and exited scrim follow `TerminalHost.visibleSessionID`, not `AppState.selection` — driving them from the selection drew a blank grid where the empty state belongs. **Reopen is lazy and happens on first show**: `applySelection` finds the host has nothing for the selected row and `live == nil`, and `reopen` restores the `.ghsnap` under a fresh shell — the old screen with a new prompt beneath it — in the directory a resume would use. A row hung up with ⌘W is deliberately *not* reopened by selection (the host still holds its dead grid, and `visibleSessionID` is set), so it stays dead under the scrim until resumed; the reopen then restores from that live grid rather than the stale file. Nothing is typed by a reopen. **Reopen failures are a notice, never a modal**: the reopen runs inside the store observer and at `init`, where an `NSAlert.runModal` would block every window test (and `~/dev/aira` exists on this machine, so fixture rows *do* pass the directory check). A row whose directories are all gone shows *"Directory missing · <path>"* in the empty state. **Resume** (⌘R, the row's context menu, *Resume all in group* on the group's, the *Auto-resume Sessions on Launch* toggle in the app menu → `AppState.autoResumeOnLaunch`, persisted under `preferences`): `reopen` if there is no shell, then `claude --resume <claudeSessionId>` — through `runWhenReady` on a fresh shell, `run` on one already at its prompt (which produces no output for the readiness path to wait on). Enabled iff `claudeSessionId != nil` and no descriptor is bound; a row with no conversation just gets its shell back. The directory is the first of `Session.resumeDirectoryCandidates` that exists — the worktree while `isWorktree`, then **`cwd`, then `repoRoot`** (design said `repoRoot ?? cwd`; `cwd` is where Claude actually ran, which for a fixed-path preset is the project `--resume` looks under, and for every other launch the two are the same directory). A worktree that is gone falls through and **clears the `WT` badge** (`clearWorktreeBadge`, path kept for the message). Resuming the *selected* row replaces its host session, which detaches the surface, and the unchanged selection would never re-show it — `resumeSession` re-applies the selection explicitly (a test models the eviction in the spy host for exactly this). Auto-resume runs **after** `ClaudeIntegration.start()` so every `claude --resume` goes through the shim the installer just wrote.
- **Worktrees after an exit**: `claude -w` offers to remove its worktree when the conversation ends, which is *before* the shell exits. So both the shell's `.exited` and Claude's exit (`ClaudeIntegration.onClaudeExited`: descriptor removed, or a `SessionEnd` that is an exit) call `SessionLauncher.noteExit`, which re-reads `git worktree list --porcelain` for that repo root (`GitStatus/WorktreeList`, `--no-optional-locks`, `GIT_OPTIONAL_LOCKS=0`, off the main actor, 300 ms debounce per repo) and clears the badge from rows whose worktree git no longer lists. Standardized-path comparison, so a trailing slash cannot make a present worktree look absent.
- **Snapshots**: every session at quit (`snapshotAll`, which skips what the idle compressor already saved — the activity token is the dirty flag), and **every 5 min** (`MainWindowController.snapshotInterval`) for live sessions, same skip. "Bounded scrollback" is not applied: perf.md §2 measured that `TerminalSession` has no live scrollback setter and that bounding is second-order (realistic snapshots ≈ 1 MiB against 22–27 MiB live), so the setter was not built for this. **Housekeeping at launch** (`AppDelegate.housekeepSnapshots`): `.ghsnap` files no row in `state.json` claims, and stale temp files, are deleted — TKZ-29 left this to M5.2.
- **Two known gaps, recorded not fixed** (2026-09-08): (1) *stale exit after a reopen* — `evict` cancels the old session's pump, but an `.exited` it already yielded into the host's merged stream stays buffered, and if it lands after `reopen` adopted the new shell, `handle(.exited)` closes the freshly resumed row; realistic when the old shell is slow to die (Claude with children under SIGHUP). The cheap guard is an `isAlive(_:)` on the protocol (`TerminalViewHost` has one) and skipping the close when the host says the id is alive. (2) *first-launch ordering* — the selected row's lazy reopen runs inside `MainWindowController.init`, before `ClaudeIntegration.start()` installs the shim, so on a fresh install (or right after *Remove Shell Integration*) that one shell has no ZDOTDIR wrappers and a `claude --resume` typed into it bypasses the shim (attribution falls back to the ppid walk, hooks are absent). Auto-resume is ordered correctly; only the pre-selected row is affected, and only on the first launch after an install.
- **Close** (⌘W, context menu): confirm when `working` or `waiting`; SIGHUP; the row stays with its screen and is resumable. **⌘W on a row that has already exited removes it, unconfirmed** (Thomas, 2026-09-08: "cmd-w for an exited session should remove the workspace") — so ⌘W twice is hang up, then clear; there is nothing left to lose but the snapshot, and the conversation is Claude Code's. **Remove** (⇧⌘W = `closeSession`, context menu): always confirmed, `TerminalHost.discard` (snapshot included) then `removeSession`; **never touches the worktree on disk**. The ticket lists ⇧⌘W under Close; design.md's own gloss ("`closeSession` (remove the row)") and cmux's ⇧⌘W = close workspace tie-break toward Remove. **Rename** (⇧⌘R, context menu) sets `Session.title` only. The sidebar's context menus are `SidebarOutlineView.menu(for:)` → the controller builds them per row id, without moving the selection (Remove on a row you are not looking at must not first switch the terminal to it); Resume from a menu *does* select the row, Resume-all does not.
- `Session.live` (pid, descriptor, status, attention, last Stop, git, ports, sidecar) is process state and is **never persisted**: `Session`'s `CodingKeys` omit it and `Session.status` is `live?.status ?? .exited`, so a restored row is `exited` and resumable by construction.
- `state.json` v1 `{schemaVersion, groups[], sessions[], presets[], selection, sidebar {visible,width}, windowFrame {x,y,width,height}, shortcuts, preferences {autoResumeOnLaunch}}` (`preferences` since M5.2, optional on read so an older file still loads — a new switch is not a schema bump); 500 ms debounced atomic write + `.bak`; corrupt → `.bak` + notice. Implemented in M5.1 (`Persistence/{StateFile,PersistedState,Migrations,StateAutosaver,JSONValue}.swift`):
  - **`collapsedGroups` is not a key.** `Group.isCollapsed` is already persisted with the group and is already the single source the outline view renders from; a second copy would be two truths that can drift.
  - **`PersistedState` is a projection, never `AppState` encoded.** `[GroupID: Group]` would encode as a flat `[k,v,k,v]` array, `CGRect` as `[[x,y],[w,h]]`, and `accounts`/`usage` are rediscovered rather than restored. The projection also **clears `live` in memory**, not only on the way to JSON: `StateAutosaver` decides whether to write by comparing two projections, so one carrying process state would differ on every status flip and the comparison would filter nothing. Date strategy stays `.deferredToDate` — `.iso8601` truncates sub-seconds and breaks `createdAt` equality on a round trip.
  - **Rotation** is `write+fsync tmp` → `link(state.json → .bak.new)` → `rename(.bak.new → .bak)` → `rename(tmp → state.json)`. `rename(primary → .bak); rename(tmp → primary)` leaves a window with **no primary**; `unlink(.bak); link(primary → .bak)` leaves a window with **no backup**, and opens it exactly when the backup is the only good copy (after a recovery the primary has been quarantined, so `link` fails ENOENT). Measured with `scripts/state-crash-test.sh`: 50 SIGKILL rounds, every survivor parsed, no round lost its state — and it caught a stranded `.bak.new` in ~1 round in 7, now swept at load.
  - **Recovery**: a `.backup` load quarantines the corrupt primary as `state.json.corrupt-<ts>` *before returning*, or the next save's `link` would copy the corruption over the only good backup. A missing primary with a good `.bak` is recovery, not corruption. `schemaVersion > 1` refuses to load **and latches the writer off** — it does not fall back to an older `.bak`, which would mean writing v1 over what a newer build stored.
  - **Unknown top-level keys** are kept in `StateDocument.extras` and re-emitted, so running an old build once does not delete a new build's fields; nested unknown keys are not preserved. `extras` can never shadow a key this build owns. Migrations run on the raw JSON object, before typed decoding — a v2 file whose `sessions[]` changed shape cannot be decoded as v1 in order to be migrated.
  - **The notice** is `StatusBarModel.notice`, a transient message that takes over the 30 pt strip for 10 s. It is deliberately not in `AppState`: `statusModel(for:)` stays a pure function of persisted state.
  - `TKZMUX_FIXTURE=1` neither loads nor saves.
